# Complementary validation in LTspice / Touchstone

**Qualitative and independent** validation of the article's chain in a
circuit engine (LTspice, a time-domain SPICE solver), distinct from the
frequency-domain pipeline in Python. It provides complementary cross-validation without requiring hardware measurements.

The idea is not to repeat the BER sweep in LTspice (not advisable; see below),
but rather to **demonstrate that the chain the paper simulates in Python holds up in an
independent circuit simulator**: same parameters, same PRBS, and the
eye diagram / Bode reproduced by LTspice match Python.

---

## 1. Implemented flow

```
   Python (generates stimuli)            LTspice (.tran / .ac)            Python (post)
 ┌───────────────────────────┐   ┌──────────────────────────────┐   ┌──────────────────┐
 PRBS-23 → PAM-4 → tx.pwl ───────► Vtx →[FFE]→[CHANNEL]→(+noise)─────►  eye diagram
 AWGN noise σ=0.10 → ruido.pwl     →[CTLE]→[RX-LPF]→ V(out) .raw      crossing vs Py twin
 causal twin → ref_python.npz                                        Bode LTspice vs Py
 └───────────────────────────┘   └──────────────────────────────┘   └──────────────────┘
```

Each LTspice block is in `bloques.lib` with **the parameters taken
literally** from `parametros.py` / `cadena_enlace.py` / `modelo_rc.py`.

## 2. What transfers cleanly to LTspice and what does NOT

| Block | In LTspice | Comment |
| :--- | :--- | :--- |
| **RC N=5 staircase** | real R/C (`rc_n5`) | 5×(R=16 Ω, C=1 pF), open-ended. Native and exact. |
| **CTLE** | `Laplace=` (`ctle`) | Transfer function with poles/zero. Valid in `.ac` **and** `.tran`. |
| **TX FFE** | `delay()` (`ffe`) | 3-tap delay line at 1/2 UI. Behavioral. |
| **RX LPF** | `Laplace=` (`rxlpf`) | Causal 3rd-order Butterworth. |
| **Pre-CTLE noise** | PWL from Python | exact σ and **identical sample-by-sample** to the twin. |
| **Dispersive channel (.s2p)** | vectorfit → `delay()`+`Laplace=` | See §4. |

### What is NOT advisable to do directly in LTspice
- **The dispersive channel EYE in transient.** The skin-effect loss
  grows as **√f**, which is **non-rational** (infinite-slope cusp at DC):
  a compact rational `Laplace` follows it with 4–5 dB of error, and forcing more poles
  yields huge coefficients that cancel out (unusable in SPICE). Moreover the **dielectric**
  loss (`G=ωC·tanδ`) requires the imaginary unit `j` in the `Laplace`,
  which LTspice does not accept in its syntax. → The dispersive channel is validated in LTspice
  **in frequency** (`disp_bode.cir`, vector-fit of the `.s2p`) and its **eye is obtained
  in Python** (exact FFT of `H(f)`). The LTspice eye is compared with Python
  on the **RC channel** (the article's central model).
- **Importing an arbitrary `.s2p` for transient.** LTspice does **not** have a
  native block that consumes measured S-parameters in `.tran` (the `W`/LTRA is for
  RLGC, not for S-params). For the frequency crossing, **vector-fitting**
  of the `.s2p` to a stable rational + delay is used (`vectorfit_s2p.py`).
- **Reproducing the BER / Monte-Carlo sweep in LTspice.** Thousands of
  realizations × rates is inefficient in a circuit solver; that stays in
  Python (where the paper's statistics live). LTspice validates the **physics of
  the waveform and the eye**, not the statistics.
- **The adaptive DFE** (data-aided decision-feedback): it is DSP logic,
  not an analog circuit; it stays in Python.
- **PRBS/PAM-4 with LTspice logic sources.** It is fragile and would not match the
  paper's PRBS → it is injected as **PWL** generated by Python.

## 3. How to run everything

**Automatic (recommended):**
```bash
cd validacion_ltspice
python correr_ltspice.py          # vectorfit + Bode + RC chain + eye + crossings
```
The runner locates LTspice (`...\AppData\Local\Programs\ADI\LTspice\LTspice.exe`);
if not, pass it with `--ltspice "PATH"`.

Options: `--bode` (Bode only), `--cadena` (eye only), `--vectorfit`,
`--baud 8e9`, `--canal fr4|megtron6|rc`.

**Manual (in the LTspice GUI):**
1. `python generar_tx_pwl.py` → creates `tx.pwl`, `ruido.pwl`, `tx_meta.inc`, `ref_python.npz`.
2. Open `cadena_completa.cir` in LTspice → **Run** (or `LTspice -b cadena_completa.cir`).
3. `python eye_desde_ltspice.py` → eye diagram + crossing.
4. For Bode: run `rc_bode.cir` and `ctle_bode.cir`, then `python comparar_bode.py`.
5. For the dispersive channel: `python vectorfit_s2p.py`, uncomment in
   `cadena_completa.cir` the line `.include disp_lines.lib` and `Xch a b disp_fr4`,
   and regenerate stimuli with `--canal fr4`.

## 4. Dispersive channel: vector-fitting (frequency validation)

`vectorfit_s2p.py` approximates each `.s2p` **for the frequency crossing** (`.ac`):

    S21(f) ≈ R(s) · exp(−s·Td)

- **Td** = bulk group delay (provided by an ideal `delay()`).
- **R(s)** = **stable** rational (poles reflected to the left half-plane, which
  preserves |H| exactly), fitted by Sanathanan–Koerner iteration with
  real coefficients.

It generates `disp_lines.lib` (subcircuits `disp_fr4`, `disp_meg`) and
`fig_vectorfit.png`. It is validated with `disp_bode.cir` + `comparar_bode.py`
(LTspice `.ac` vs `.s2p`, <0.6 dB ≤15 GHz). The Python path
(`LineaTransmision.H`) is the ground truth and produces the **dispersive eye**
(in `simulacion_ojo.py`), which is NOT done in LTspice for the reasons stated in §2.

## 5. Validation results (already executed)

| Check | Result |
| :--- | :--- |
| RC staircase `.tran` (step) vs `CanalRCEscalera` | max **0.0019** (≈0.2 %) |
| Bode RC N=5: LTspice vs Python | **0.000 dB** |
| Bode CTLE: LTspice vs Python | **0.000 dB** |
| Vector-fit S21 (FR-4 / Megtron) vs `.s2p` | **0.25 / 0.27 dB** (order 6) |
| Dispersive in LTspice (`.ac`) vs `.s2p` | **0.55 dB** (≤15 GHz) |
| **Full chain (RC): LTspice vs Python twin (waveform)** | **RMS = 0.09 %** of span |
| **Eye (RC): opening per sub-eye, LTspice vs Python** | max Δ **0.011 V** (≈0.5 %) |
| **Eye (RC): sampled levels μ, LTspice vs Python** | max Δ **0.009 V** |

(Eye diagram compared side by side in `fig_comparacion_ojos.png`:
Python | LTspice | overlaid — the eyes match visually and metrically.)

Conclusion: an independent circuit engine reproduces the article's chain
with sub-0.1 % error in the waveform and sub-1 % in the eye opening, on the
RC channel (central model). The dispersive channel is cross-checked in frequency (<0.6 dB) and
its `.s2p` + `disp_lines.lib` are the direct bridge to SPICE/ADS. Suitable
as complementary journal validation.
